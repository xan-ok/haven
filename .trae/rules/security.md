# 安全专项规则

本文件只补充安全敏感代码的额外约束；通用开发规则见 `AGENTS.md`。

## 密钥生命周期

- 主密钥只允许存在于 Rust 侧，不得通过 Tauri 命令、事件或序列化结构返回前端。
- 新增持有密钥、派生密钥或密码的结构体，必须使用 `Zeroizing` 或实现清零的 `Drop`。
- 锁定、退出、错误路径都要清理密钥；不得因为提前 `return` 漏清。
- 不得把密钥写入配置文件、缓存、日志、错误信息、崩溃信息或测试快照。

## 密码与派生

- 校验规则必须与 PRD 一致：长度按 Unicode 码点计算，不 trim、不归一化、不静默修改。
- 禁止自行发明 KDF 或加密流程；只能使用经过审查的成熟库。
- KDF 参数变更必须保持旧保险库可解锁，并在元数据中保留参数。

## 加密 API 使用

- AEAD 的 nonce 不得复用；nonce 必须由安全随机数生成并随密文保存。
- AAD 必须覆盖所有未加密但参与语义的元数据字段；新增字段时必须同步更新 AAD 构造与校验。
- 解密失败、认证失败必须返回统一错误，不区分“密码错”和“数据损坏”的内部细节。

## 随机数

- 只使用操作系统 CSPRNG（如 `OsRng` / `getrandom`）。
- 禁止用时间戳、计数器、进程 ID、`Math.random` 或可预测值生成密钥、盐值、nonce。

## 错误处理与日志

- 对外错误码不得包含文件路径、文件名、密码、密钥或明文内容。
- 不得用 `unwrap` / `expect` 处理外部输入或磁盘错误；不得让 panic 信息携带敏感数据。
- 日志只记录稳定错误码与阶段，不记录用户数据。

## 元数据校验与资源消耗

- 校验版本、算法标识、字段长度、base64 解码结果与 KDF 参数范围。
- 对 KDF 内存、迭代次数、并行度设置上限，防止恶意元数据造成资源耗尽。
- 缺失或损坏的元数据不得触发自动重建或覆盖写入。

## 内存与明文残留

- 密码、派生密钥、明文缓冲区在使用后清零；避免不必要的 `clone` 与 `String` 驻留。
- 临时文件必须有明确的创建、替换、失败清理路径；失败不得留下有效半成品。
- 不得声称普通删除等于安全擦除，也不得承诺清除操作系统层面的残留。

## 权限与配置

- `capabilities/` 与 CSP 遵循最小权限；新增权限必须说明用途和影响范围。
- 不得为调试方便放开文件系统、shell 或网络权限。

## 测试要求

- 必须覆盖：错误密码、元数据篡改、元数据缺失、参数越界、锁定后访问、失败不留半成品。
- 测试通过不等于安全；失败场景缺失本身就是问题。
- 测试代码不得输出密码、密钥或真实敏感文件内容。
